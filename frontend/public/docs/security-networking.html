Network posture

The storage account accepts only Microsoft Entra-authenticated access. Anonymous Blob access and shared-key authentication stay disabled. The app and ingestion jobs receive only the data-plane roles they need.

The public deployment code does not create an external Strategy credential. Production operators must configure that integration under the organization's approved network and identity controls.

Canonical source: security/auth.md

Identity and access

Public visitors do not sign in.

Azure writer

The ingestion process uses the developer or managed identity with Storage Blob Data Contributor. It can write current and archive files.

Strategy connector

The public source does not create or store a Strategy credential. A connector must be configured by the deployment operator with an identity approved by the organization. Connector names, resource IDs, users, and secrets remain outside the repository.

Shared-key protection

The Bicep deployment disables storage shared-key authentication. Public access does not mean credential-free access: anonymous Blob access is off, and Microsoft Entra role-based access controls the data plane.

Canonical source: security/secrets.md

Secrets

The public repository and app settings contain no storage keys, client secrets, passwords, or access tokens.

The application reads and writes ADLS with Microsoft Entra managed identity. Shared-key storage authentication is disabled in the public Bicep deployment.

An external Strategy connector is an optional, environment-specific integration. Configure it outside this repository with the organization's approved identity and secret-management controls. Never copy connector values, screenshots of credential screens, or temporary passwords into source control.

Canonical source: security/privacy.md

Privacy

The ADLS export uses an allowlist. It excludes:

  • apartment;
  • house number;
  • street name;
  • coordinates;
  • 311 incident address;
  • 311 resolution text;
  • owner-person data;
  • tenant data; and
  • names, email addresses, and phone numbers.

The public app receives counts, building IDs, source dates, boroughs, rule version, and safe process metadata. It does not receive a raw complaint problem, raw violation candidate, or 311 resolution record.

The browser session ID is random and is not authentication. It stays in session storage and is not persisted by the server.

Real public addresses remain blocked until privacy and template-owner review.

Canonical source: security/rate-limiting.md

Rate limiting

Practice review runs are limited to six starts per minute for each combination of source address and random browser session ID. A request must name a saved scenario. Arbitrary prompts and building IDs are not accepted.

The in-memory limit is suitable for local testing only. Before public release, use a shared server-side store so the limit cannot be bypassed by starting a new container replica.

The app must also enforce:

  • maximum request bytes;
  • maximum run duration;
  • maximum records per run;
  • maximum output and citation size;
  • bounded concurrent runs; and
  • a global quota with a server-enforced stop.
Canonical source: adr/0011-managed-identity-only-public-infrastructure.md

ADR 0011: Keep the public deployment identity-only

  • Status: accepted
  • Date: 2026-11-24
  • Context: The demo is published from a public repository. Deployment-specific

identifiers, connector credentials, personal ownership records, and policy bypass automation must not be part of public history.

  • Decision: Publish identity-only Bicep. Disable anonymous Blob access and

shared-key storage authentication. Keep external connector credentials and live resource IDs in the authorized deployment environment.

  • Consequences:

- Good: a public clone contains no storage key, connector password, or live Azure resource identifier. - Good: the data plane uses Microsoft Entra role assignments and managed identity. - Bad: an external Strategy connector needs a separate, approved operator setup. - Mitigation: the public runbook explains the boundary without publishing connector values.
